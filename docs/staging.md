# Staging stack

```
make up          # build, start, wait for health, seed (first run: ~5-10 min)
make test        # service + JS lint and tests
make test-moodle # PHPUnit for both plugins inside the moodle container
make e2e-gate    # M2 gate end to end: token -> service -> signed webhook -> attempt link (17 checks)
make test-browser # real Chromium, fake camera + screen: pre-check, forged start refused,
                 # exam shell capture across page changes and a 60 s offline window (~2 min)
make test-browser-agiledev # all 11 browser tests against agiledev, none skipped (~7 min):
                 # service SQL, kill switch and attempt lookup run over SSH (REMOTE_SSH)
make sdk-moodle  # rebuild client-sdk into the plugin's amd/ folder
make down        # stop; make reset also deletes data volumes
```

| Service | URL | Notes |
| --- | --- | --- |
| Moodle 4.5.1+ (Build 20250131), PHP 8.1 | http://localhost:8080 | admin password: `MOODLE_ADMIN_PASSWORD` in `staging/.env` (generated, git-ignored) |
| ExamProctor service (browser-facing) | http://localhost:8000/v1/health, `/v1/health/ready` | readiness checks Postgres, Redis, object store |

Seeded synthetic data: course `EP-STAGING-101`, quiz "Proctored practice quiz" (5 true/false, 15 min), users `epteacher`, `epinvigilator`, `epreviewer`, `epstudent01`..`epstudent20` (password `SEED_USER_PASSWORD`, default `Staging#2026`). Seed is idempotent.

Plugins are bind-mounted read-only from `moodle/`; after editing a plugin's version, run `docker compose -f staging/compose.yml --env-file staging/.env exec -u www-data moodle php admin/cli/upgrade.php --non-interactive`.

Signing secrets for Moodle <-> service live in `staging/examproctor.secrets` (generated by make, git-ignored) and are copied into the Moodle settings by `make seed`.

## M3 capture notes

- Staging intervals: camera 10 s, screen 15 s (production defaults 30 s / 60 s, site settings in local_examproctor).
- Evidence store: SeaweedFS S3 on `localhost:8333`, credentials from `staging/examproctor.secrets`, volume data encrypted (`-s3.encryptVolumeData`). Checked: objects read back as JPEG through S3; raw volume files contain no JPEG markers.
- Measured on staging: camera snapshot ~7 KB, screen ~10 KB (fake devices; real cameras will be larger, budget 30-60 KB).
- Known limits, to address before load tests (M7):
  - SeaweedFS answers CORS for any origin by default; production must restrict to the Moodle origin.
  - `uploads/complete` re-reads each object to check sha256. At 270 images/s this doubles store reads; M4 moves the check into the analysis worker, which reads the image anyway.
  - Retention counts 90 days from session end until Moodle reports "results finalised" (M5).
